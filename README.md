# Industrial Vision — компьютерное зрение и Edge AI

Учебный программный модуль технического зрения для промышленного мобильного роботизированного комплекса. Система анализирует видеопоток локально, отслеживает объекты, контролирует заданные области и формирует события с подтверждающими изображениями.

Проект разработан в рамках лабораторной работы «Разработка программного модуля технического зрения для промышленного мобильного роботизированного комплекса» (НГТУ, 2026).

## Возможности

- **Базовая детекция:** обнаружение людей и транспорта с помощью YOLO26n.
- **Tracking:** присвоение и сопровождение `Track ID` между кадрами.
- **ROI:** контроль попадания людей и транспорта в многоугольную область; отдельные события для каждой категории. Проверку ROI можно выключить в конфигурации.
- **PPE:** обнаружение касок и сигнальных жилетов, формирование событий при их отсутствии.
- **Fire / Smoke:** обнаружение признаков огня и дыма с временным подтверждением.
- **Spill:** экспериментальное обнаружение разливов жидкостей.
- **Event Engine:** локальное сохранение событий в JSONL и подтверждающих изображений.
- **REST API:** чтение событий и проверка состояния сервиса через FastAPI.
- **Edge AI:** запуск базового детектора на CPU, экспорт в ONNX и сравнение производительности.


## Технологии

Python 3.12, OpenCV, Ultralytics YOLO, PyTorch, ONNX Runtime, NumPy, PyYAML, FastAPI, Uvicorn, pytest.

## Установка на Windows

Откройте терминал в корне проекта. Рекомендуемая версия — **Python 3.12**.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Для CPU-устройства убедитесь, что установлены необходимые зависимости PyTorch и ONNX Runtime. Если они не перечислены в `requirements.txt`, установите их дополнительно согласно совместимым версиям для вашей среды:

```powershell
python -m pip install onnx onnxruntime onnxslim
```

## Модели и видео

**Четыре готовые модели включены в репозиторий** в папке `models/`. После клонирования не требуется отдельно скачивать веса для основного запуска программы:

| Назначение | Путь в репозитории |
|---|---|
| Базовая YOLO (ONNX Runtime) | `models/detector/yolo26n.onnx` |
| Контроль касок и жилетов (PPE) | `models/ppe/best.pt` |
| Обнаружение огня и дыма | `models/fire_smoke/best.pt` |
| Обнаружение разливов | `models/spills/best.pt` |

Пути к весам указаны в `configs/configuration.yaml`. Обучающие наборы данных, промежуточные результаты обучения (`runs/`) и тестовые видео **не включены в Git** из-за размера. Для демонстрации добавьте нужный видеофайл в `data/` и укажите его имя в `camera.source`, либо используйте доступную USB/IP-камеру.

Файлы `yolo26n.pt` и `yolo26n.onnx` в корне проекта могут использоваться экспериментальными скриптами. **Для обычного запуска `main.py` достаточно модели `models/detector/yolo26n.onnx`.** Если хотите повторить эксперимент по экспорту исходной PyTorch-модели, отдельно предоставьте `yolo26n.pt` или настройте путь в скрипте экспорта.



## Запуск

1. Укажите нужный видеофайл в `configs/configuration.yaml`, например `camera.source: "data/ppe_test.mp4"`.
2. Проверьте пути к моделям в разделах `models`, `ppe`, `fire_smoke`, `spills`.
3. Включите только необходимые для демонстрации модули.
4. Выполните:

```powershell
python main.py
```

Для остановки нажмите **Q** в окне видео.

### Управление модулями

Пример для запуска только базового детектора, Tracking и ROI:

```yaml
modules:
  roi_enabled: true
  ppe_enabled: false
  fire_smoke_enabled: false
  spills_enabled: false
```

Для включения дополнительной нейросети измените соответствующее значение на `true` и перезапустите программу. Основная YOLO + Tracking работает постоянно.

Частота запуска дополнительных нейросетей задаётся отдельным параметром:

```yaml
optimization:
  extra_detection_interval: 3
```

`3` означает запуск PPE, Fire/Smoke и Spill **каждый третий обрабатываемый кадр** (если модуль включён), а не три раза в секунду. Между запусками на экране могут оставаться последние найденные рамки. Увеличение интервала повышает риск пропустить кратковременное событие и требует дополнительной проверки временной логики.

Разрешение базовой нейросети задаётся параметром `models.image_size`; разрешения Fire/Smoke и Spill настраиваются отдельно.

## События и результаты

Основные типы событий:

- `person_in_restricted_zone` — человек в ROI;
- `vehicle_in_restricted_zone` — транспорт в ROI;
- `ppe_helmet_missing` — отсутствует каска;
- `ppe_vest_missing` — отсутствует жилет;
- `fire_detected` — обнаружен огонь;
- `smoke_detected` — обнаружен дым;
- `spill_detected` — обнаружен разлив.

События сохраняются в `output/events.jsonl`, изображения — в `output/evidence/`. Доступность конкретного события зависит от тестового видео, порога уверенности и временного подтверждения.

## REST API

Запуск в **отдельном терминале** из корня проекта:

```powershell
python -m uvicorn src.api.server:app --host 127.0.0.1 --port 8000
```

Примеры адресов:

- `http://127.0.0.1:8000/health` — состояние API;
- `http://127.0.0.1:8000/events` — события;
- `http://127.0.0.1:8000/events/{event_id}` — событие по идентификатору;
- `http://127.0.0.1:8000/evidence/{event_id}` — подтверждающий снимок;
- `http://127.0.0.1:8000/stats` — статистика;
- `http://127.0.0.1:8000/docs` — интерактивная документация FastAPI.

API читает локально сохранённые события. Сам запуск API **не запускает** цикл обработки видео — для него используйте `python main.py`.

## Benchmark и Edge AI

Для базового сравнения PyTorch и ONNX на CPU:

```powershell
python -m scripts.export_onnx
python -m scripts.test_onnx
python -m scripts.compare_pytorch_onnx
```

Скрипты первоначально рассчитаны на `yolo26n.pt` и `yolo26n.onnx` в корне проекта, а также на `data/ppe_test.mp4`. Для повторения сравнения после переноса весов в `models/` скорректируйте пути в скриптах. Экспорт из `.pt` выполняется только при наличии исходного файла PyTorch; готовый `models/detector/yolo26n.onnx` уже подходит для работы основного приложения.

Измерения на ноутбуке **Intel Core i3-6006U**, CPU, разрешение 320×320, 300 измеряемых кадров:

| Показатель | PyTorch | ONNX Runtime |
|---|---:|---:|
| FPS | 10,21 | 12,08 |
| Средняя задержка | 97,96 мс | 82,75 мс |
| P95 | 122,42 мс | 119,39 мс |
| Максимальная задержка | 159,74 мс | 218,85 мс |
| Размер файла модели | 5,29 МБ | 9,35 МБ |

ONNX показал ускорение по FPS примерно на **18,3%** в этом эксперименте. Результаты сохранены в `output/benchmark_onnx.csv` при запуске скрипта.


Для стандартного Benchmark проекта:

```powershell
python -m scripts.benchmark
```

Набор проверяемых конфигураций A/B/C/D определяется в самом скрипте `scripts/benchmark.py`; на ноутбуке он мог быть временно ограничен конфигурацией A.

## Ограничения и статус

- Пропуск кадров уменьшает нагрузку, но увеличивает интервал между проверками событий.
- Качество распознавания зависит от размеров объектов и освещения; снижение разрешения может ухудшить детекцию.
